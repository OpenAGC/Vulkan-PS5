# FW 5.50 3D and self-image blit qualification

Date: 2026-08-01  
Endpoint: standard PS5, system software `5.500.008`  
Probe: `vulkan_ps5_blit3d_probe.elf`

## Oracle

The cleanup-guarded probe records two Vulkan operations in one native graphics
queue stream:

- a nearest-filtered 4x4x4 3D-to-3D color blit, checked as 64 exact pixels;
- a nearest-filtered 8x8 mip-zero to 4x4 mip-one self-image blit, checked as
  16 exact pixels after disjoint per-subresource transitions.

The fence wait is bounded at two seconds. Success additionally requires clean
system-service exit, attributable kernel lifecycle evidence, process absence,
and immediate websrv availability.

## Discovered runtime bug

The first candidate (`61a4a2f78a20ba23d3a9ac35a92ea4e5d715b47b5d686dde9c7b351aaecd98cc`)
passed all four 3D slices but failed the self-image mip oracle. A diagnostic
replay showed that a single-mip 2D source view still encoded the complete
multi-mip allocation. Gfx1013 therefore applied native mip-chain addressing
instead of OpenAGC's queried linear subresource layout.

OpenAGC now rebases a single-mip 2D view to that mip's queried address and
extent and encodes it as a one-level resource. Multi-mip views remain
allocation-relative. Exact descriptor tests cover base-zero and nonzero-base
single-mip views.
