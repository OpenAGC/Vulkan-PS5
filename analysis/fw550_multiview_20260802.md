# FW 5.50 multiview qualification — 2026-08-02

## Result

Basic Vulkan multiview is host- and FW 5.50-qualified through public OpenAGC
APIs. The probe uses one six-layer RGBA8 image, legacy render-pass view mask
`0x21`, one draw, and host-visible readback. Both guarded runs produced:

```
multiview: PASS mask=0x21 view0=ff0000ff view5=ffff0000
```

The qualified ELF SHA-256 is
`00b5361b49d00fdb133ce2e2882618be82cba918df7b83732e268b8a96b01e22`.
The cleanup prerequisite SHA-256 is
`9fd6b41cf2ea87989c4217234c6f34c96a1ca5dc482355af1258539db77d4d76`.

## Implementation boundary

- Dedicated and Vulkan 1.1 feature/property queries advertise basic
  multiview with six views. Multiview geometry and tessellation remain false.
- RenderPass, RenderPass2, and dynamic-rendering view masks are validated
  against the six-view limit and attachment layer ranges.
- Each active view is replayed as an ordered native draw. Vulkan supplies the
  view mask; OpenAGC's typed `agcCmdSetViewIndex` programs the reflected
  `ViewIndex` value and the attachment binder selects the matching array layer.
- openagc-psbc preserves vertex `ViewIndex`, exports it as `Layer`, and lowers
  fragment `ViewIndex` to the fragment ancillary layer input. No raw SGPR or
  GPU-address interface is exposed by Vulkan.

## Regression found before qualification

The first diagnostic ELF
`f767d40342ba26d90f041bab3316dcaa5db830de859779be03821dc19a5a6780`
failed in userspace during fragment compilation at
`ac_nir_load_arg_at_offset(arg.used)`. RADV had lowered fragment `ViewIndex`
to `Layer`, but the standalone compiler did not retain the ancillary input
through pixel-argument compaction. No draw was submitted, no residual process
remained, and this was not a kernel panic. That artifact must not be rerun.

The fix preserves `SYSTEM_VALUE_LAYER_ID` before shader-info computes
`SPI_PS_INPUT_ENA`. The compiler suite now covers both vertex and fragment
multiview stages, including postprocess and ACO compilation.
