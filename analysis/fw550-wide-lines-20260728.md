# FW 5.50 Wide-Lines Qualification

`wideLines` was qualified with a bounded line-list readback probe on
FW 5.500.008. It draws a static 8-pixel horizontal line, then uses
`vkCmdSetLineWidth` to draw 16- and 32-pixel lines from the same dynamic
pipeline. The oracle requires exact 1,024, 2,048, and 4,096 pixel coverage,
the expected center color, zero unexpected pixels, clean SystemService exit,
exact target-PID absence, and responsive websrv.

OpenAGC commit `949ca76` provides typed line-list/strip topology and the atomic
gfx1013 primitive-size packet. Vulkan accepts both line topologies, validates
static widths in `[1, 64]`, treats the static field as ignored for a dynamic
pipeline, persists dynamic width within command-buffer recording, and clears it
on begin/reset. Drawing with unset dynamic state fails recording. Exact command
tests lock primitive type 2 and line-control encodings `0x40`, `0x80`, and
`0x100`; normal and ASAN/UBSAN suites pass 27/27.

The internal run (`20260728T120753Z-wide-lines-run1.log`, PID 119) and public
feature-query/request run (`20260728T120940Z-wide-lines-run1.log`, PID 120)
both passed the exact oracle and exited cleanly. Their target-only klogs contain
no GPU reset or crash, only the established `amount=0x4000` baseline VM
warning. The final Prospero ELF links `-lunwind -lc++abi -lc++ -lm` and has
SHA-256
`25db7763fd45e5494067dbcf83ed16884fcfe9a6b93958b2a9d3f3e4a63fb109`.
